# 对抗性审查记录

审查日期：2026-09-11

审查对象：最初为 GPT-6 Astra 文章生成的单文件 X Articles 复制页及其构建脚本。

## 已发现并修复

1. **压缩包内存在失效链接**：旧页面的“下载整包”指向父目录；解压后父目录没有该 ZIP，按钮必然失效。新版页面删除了自引用下载按钮，由构建器在输出目录旁生成完整 ZIP。
2. **无法复用**：文章路径、六张图片的数量、文件名、插入位置和页面标题全部写死。新版从任意 Markdown 自动提取标题、图片、图注和前文定位。
3. **机器绑定**：旧脚本把 Python 依赖目录写成 `/private/tmp/astra-article-deps`。新版是标准 Python 包，通过 `pyproject.toml` 声明依赖并提供命令行入口。
4. **原始 HTML 注入**：Markdown 渲染器默认允许原始 HTML，外来的文章可以把脚本写进工作台。新版在 Markdown 解析前转义原始 HTML，并拒绝 `javascript:`、`data:` 等危险协议。
5. **本地文件越界读取**：恶意 Markdown 可以把文章目录之外的文件伪装成图片并打进发布包。新版默认限制到文章目录；包括符号链接在内的越界路径都会失败。
6. **远程图片隐私泄露**：直接预览远程图片会在打开工作台时请求第三方服务器。新版不自动加载或下载远程图片，只显示来源链接。
7. **危险覆盖**：旧构建器直接向固定目录写入，旧图片可能残留。新版先在临时目录完整构建，再原子替换；`--force` 也只覆盖带有效生成器标记的目录。
8. **列表校验漏项**：列表项内含加粗等子节点时，早期校验会在读取前修改节点，造成校验文本漏字。新版先捕获完整源文本再转换，并加入含加粗和嵌套列表的回归测试。
9. **表格粘贴不稳定**：X Articles 没有可靠的 Markdown 表格导入。新版把每行转换成带 `｜` 分隔的普通段落，保留单元格文字、加粗和链接。
10. **复制回退判断碰撞**：旧版以“正文文字是否等于标题”判断回退选区，极端情况下会选错。新版为每个复制按钮显式传入回退节点。

## 自动化覆盖

- 正文、加粗、来源链接和图片顺序。
- 封面自动识别及正文图片编号。
- 原始 HTML 不执行，危险协议失败。
- 缺图失败，远程图片不自动加载。
- 任意目录不可被 `--force` 删除。
- 仅本工具生成的目录可以安全重建。
- 嵌套列表与列表内加粗不丢失。
- Markdown 表格转换后仍可读。
- ZIP 包含工作台、清单和编号图片。

## 保留的产品边界

- X 最终会按自己的编辑器规则标准化字体和间距；工作台保留的是语义格式，包括标题、加粗、引用和链接。
- 浏览器无法把本地图片和富文本作为一次 X 上传动作可靠完成，因此图片继续采用编号上传流程。
- 工具不会登录 X、填写草稿或点击发布。
